# Архитектура

Здесь описано, из чего состоит проект и как части общаются между собой.



## Схема

```
mermaid
flowchart LR
    subgraph B\\\\\\\\\\\\\\\[Браузер]
        P\\\\\\\\\\\\\\\[Страницы: Tabler + JavaScript fetch]
    end
    subgraph S\\\\\\\\\\\\\\\[Сервер приложений - Render]
        G\\\\\\\\\\\\\\\[Gunicorn]
        W\\\\\\\\\\\\\\\[WhiteNoise - статика]
        D\\\\\\\\\\\\\\\[Django]
        A\\\\\\\\\\\\\\\[REST API - DRF]
    end
    DB\\\\\\\\\\\\\\\[(База данных<br>PostgreSQL или SQLite)]
    P -- "HTTPS: страницы и JSON" --> G
    G --> W
    G --> D
    D --> A
    D -- ORM --> DB
    A -- ORM --> DB
```



## Части проекта

|**Часть**|**Что делает**|
|-|-|
|Браузер|Показывает страницы. JavaScript через `fetch` отправляет запросы в API и получает JSON, поэтому страница не перезагружается|
|Gunicorn|Принимает запросы на сервере (на Render) и передаёт их Django. Локально вместо него работает `runserver`|
|Django|Выбирает нужную функцию по адресу, строит страницы из шаблонов, проверяет вход, CSRF и права|
|REST API|Адреса `/api/...`, которые принимают и отдают JSON. Данные проверяют сериализаторы|
|База данных|Хранит данные. Django работает с ней через ORM. Локально SQLite, на Render PostgreSQL|
|WhiteNoise|Отдаёт статические файлы (стили, Tabler, скрипты)|



## Приложения

* `accounts` – вход, профиль, подразделения, курсы, группы, дашборды.
* `tickets` – заявки (`/api/categories/`, `/api/tickets/`).
* `bookings` – бронирование оборудования (`/api/equipment/`, `/api/bookings/`).



## Как проходит запрос

Например, студент создаёт бронь:

1. Страница отправляет `POST /api/bookings/` с JSON.
2. Gunicorn передаёт запрос Django.
3. Django проверяет, что пользователь вошёл и есть CSRF-токен.
4. Сериализатор проверяет данные (цель не короче 5 символов и т. д.).
5. Бронь сохраняется в базе вместе с записью в истории.
6. Сервер отвечает `201` и JSON брони, страница обновляет список.



## Границы между частями

* Браузер и сервер общаются только по HTTP: страницы приходят как HTML, данные как JSON. Сервер проверяет всё, что прислал браузер.
* С базой работает только Django через ORM. Адрес базы берётся из переменной `DATABASE\\\\\\\\\\\\\\\_URL`.
* Все страницы и весь API закрыты без входа. Открыт только `/healthz/`.
* Студент видит только свои заявки и брони, методист и администратор видят все.
* Секреты (ключ, адрес базы) лежат в переменных окружения, а не в коде.



## Статические файлы

Стили и Tabler лежат в папке `static/`. Команда `collectstatic` в `build.sh` копирует их в `staticfiles/`, оттуда их отдаёт WhiteNoise. Папка `staticfiles/` в Git не хранится.



## Локально и на Render

||**На компьютере**|**На Render**|
|-|-|-|
|Сервер|`runserver`|Gunicorn|
|База|SQLite (`db.sqlite3`)|PostgreSQL|
|`DJANGO\\\\\\\\\\\\\\\_DEBUG`|`True`|`False`|

Локальная и облачная базы – разные. Данные между ними не переносятся.
