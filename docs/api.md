# REST API

Здесь описаны все маршруты API проекта.



## Общие правила

* Все адреса начинаются с `/api/`.
* Нужно войти на сайт (`/accounts/login/`). Без входа сервер отвечает `403`.
* Для `POST`, `PUT`, `PATCH` и `DELETE` нужен заголовок `X-CSRFToken`. JavaScript страниц добавляет его сам.
* Запросы и ответы – JSON.
* Студент видит только свои заявки и брони. Чужие для него не существуют: ответ `404`.
* Методист (группа «Методист») и администратор видят все заявки и брони.
* Ошибки приходят так: `{"purpose": \["Цель должна содержать не менее 5 символов."]}` (ошибка в поле), `\["Недопустимый переход статуса."]` (общая ошибка) или `{"detail": "..."}` (нет прав, не найдено).



## Все маршруты

|**Метод**|**Адрес**|**Что делает**|
|-|-|-|
|GET|`/healthz/`|Проверка, что сервер работает (без входа)|
|GET|`/api/categories/`|Список категорий|
|GET|`/api/tickets/`|Список заявок (`?status=`)|
|POST|`/api/tickets/`|Создать заявку|
|GET, PATCH, PUT, DELETE|`/api/tickets/{id}/`|Одна заявка: получить, изменить, удалить|
|GET|`/api/equipment/`|Оборудование и остатки|
|GET|`/api/bookings/`|Список броней (`?status=`, `?equipment=`)|
|POST|`/api/bookings/`|Создать бронь|
|GET, PATCH, PUT, DELETE|`/api/bookings/{id}/`|Одна бронь: получить, изменить, удалить|
|POST|`/api/bookings/{id}/confirm/`|Подтвердить бронь|
|POST|`/api/bookings/{id}/complete/`|Завершить бронь|
|POST|`/api/bookings/{id}/cancel/`|Отменить бронь|
|GET|`/api/bookings/{id}/history/`|История брони|
|GET|`/api/bookings/stats/`|Сколько броней в каждом статусе|

Для `PATCH` отправляют только изменяемые поля. Для `PUT` нужно отправить все.

## Категории

### GET /api/categories/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Получить список категорий заявок|
|Аутентификация|Нужен вход|
|Тело запроса|Нет|
|Успех|`200`, `\[{"id": 1, "name": "Оборудование"}, ...]`|
|Ошибки|`403` – не вошли на сайт|
|Проверка|Открыть адрес в браузере после входа: виден JSON|



## Заявки

### GET /api/tickets/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Список заявок. Студент получает свои, методист и администратор – все|
|Аутентификация|Нужен вход|
|Тело запроса|Нет. Можно добавить `?status=new` (или `progress`, `done`)|
|Успех|`200`, список заявок|
|Ошибки|`403` – не вошли на сайт|
|Проверка|В Network виден GET с кодом 200|



### POST /api/tickets/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Создать заявку (автором становится текущий пользователь)|
|Аутентификация|Нужен вход и `X-CSRFToken`|
|Тело запроса|`{"title": "Не работает проектор", "description": "Аудитория 305", "category": 1}`|
|Успех|`201`, JSON заявки со статусом `new`|
|Ошибки|`400` – название короче 5 символов или не указана категория; `403` – нет входа или токена|
|Проверка|Заявка появилась в списке и осталась после обновления страницы|



### PATCH /api/tickets/{id}/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Изменить заявку, чаще всего её статус|
|Аутентификация|Нужен вход и `X-CSRFToken`|
|Тело запроса|`{"status": "progress"}`|
|Успех|`200`, JSON обновлённой заявки|
|Ошибки|`400` – недопустимый переход статуса; `404` – заявка чужая или не найдена; `403` – нет входа или токена|
|Проверка|В Network виден PATCH с кодом 200, повторный GET показывает новый статус|

Статусы меняются только по порядку: `new` → `progress` → `done`.



### DELETE /api/tickets/{id}/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Удалить заявку|
|Аутентификация|Нужен вход и `X-CSRFToken`|
|Тело запроса|Нет|
|Успех|`204`, тела ответа нет|
|Ошибки|`404` – заявка чужая или не найдена; `403` – нет входа или токена|
|Проверка|Заявка пропала из списка|



## Оборудование

|**Параметр**|**Значение**|

|Назначение|Список оборудования с остатками|
|Аутентификация|Нужен вход|

## Бронирования

Пример брони в ответе:

```
json
{
  "id": 2,
  "equipment": 2,
  "equipment\_name": "Компьютер",
  "owner\_name": "admin",
  "quantity": 5,
  "purpose": "Тестирование",
  "status": "created",
  "status\_text": "Создана",
  "can\_manage": true,
  "created\_at": "2026-10-27T09:40:12.345678Z"
}
```

Статус брони обычным `PATCH` изменить нельзя. Он меняется только действиями `confirm`, `complete` и `cancel`.



### GET /api/bookings/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Список броней. Студент получает свои, методист и администратор – все|
|Аутентификация|Нужен вход|
|Тело запроса|Нет. Можно добавить `?status=created\&equipment=2`|
|Успех|`200`, список броней|
|Ошибки|`403` – не вошли на сайт|
|Проверка|В Network при смене фильтра виден новый GET с параметрами|



### POST /api/bookings/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Создать бронь со статусом `created` и первую запись в истории|
|Аутентификация|Нужен вход и `X-CSRFToken`|
|Тело запроса|`{"equipment": 2, "quantity": 5, "purpose": "Тестирование"}`|
|Успех|`201`, JSON брони|
|Ошибки|`400` – цель короче 5 символов или количество меньше 1 или больше, чем есть всего; `403` – нет входа или токена|
|Проверка|В Network виден POST с кодом 201, бронь осталась после перезапуска сервера|



### PATCH /api/bookings/{id}/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Изменить оборудование, количество или цель. Только пока бронь в статусе «Создана»|
|Аутентификация|Нужен вход и `X-CSRFToken`|
|Тело запроса|`{"purpose": "Защита проекта"}`|
|Успех|`200`, JSON брони|
|Ошибки|`400` – бронь уже не «Создана» или неверные данные; `404` – бронь чужая; `403` – нет входа или токена|
|Проверка|В истории брони появилась запись об изменении|



### DELETE /api/bookings/{id}/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Удалить бронь. Можно только в статусах «Создана» и «Отменена»|
|Аутентификация|Нужен вход и `X-CSRFToken`|
|Тело запроса|Нет|
|Успех|`204`, тела ответа нет|
|Ошибки|`400` – бронь в другом статусе; `404` – бронь чужая; `403` – нет входа или токена|
|Проверка|Бронь пропала из списка|



### POST /api/bookings/{id}/confirm/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Подтвердить бронь: свободного оборудования становится меньше. Статус, остаток и история меняются в одной транзакции|
|Аутентификация|Нужен вход и `X-CSRFToken`. Только методист или администратор|
|Тело запроса|Нет|
|Успех|`200`, JSON брони со статусом `confirmed`|
|Ошибки|`400` – бронь не «Создана» («Недопустимый переход статуса.») или не хватает оборудования; `403` – нет прав; `404` – бронь не найдена|
|Проверка|Статус «Подтверждена», у оборудования меньше свободных единиц, в истории новая запись|



### POST /api/bookings/{id}/complete/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Завершить бронь: оборудование возвращено, свободных единиц снова больше|
|Аутентификация|Нужен вход и `X-CSRFToken`. Только методист или администратор|
|Тело запроса|Нет|
|Успех|`200`, JSON брони со статусом `completed`|
|Ошибки|`400` – бронь не «Подтверждена»; `403` – нет прав; `404` – бронь не найдена|
|Проверка|Число свободных единиц вернулось|



### POST /api/bookings/{id}/cancel/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Отменить ещё не подтверждённую бронь|
|Аутентификация|Нужен вход и `X-CSRFToken`|
|Тело запроса|Нет|
|Успех|`200`, JSON брони со статусом `cancelled`|
|Ошибки|`400` – бронь не «Создана»; `404` – бронь чужая или не найдена; `403` – нет входа или токена|
|Проверка|Статус «Отменена»|



### GET /api/bookings/{id}/history/

|**Параметр**|**Значение**|
|-|-|
|Назначение|История действий с бронью|
|Аутентификация|Нужен вход|
|Тело запроса|Нет|
|Успех|`200`, `\[{"id": 1, "action": "Бронирование создано", "actor\_name": "admin", "created\_at": "..."}]`|
|Ошибки|`404` – бронь чужая или не найдена; `403` – не вошли на сайт|
|Проверка|После каждого действия появляется новая запись|



### GET /api/bookings/stats/

|**Параметр**|**Значение**|
|-|-|
|Назначение|Сколько броней в каждом статусе. Студент видит свои, методист и администратор – все|
|Аутентификация|Нужен вход|
|Тело запроса|Нет|
|Успех|`200`, `{"created": 1, "confirmed": 0, "completed": 0, "cancelled": 0, "total": 1}`|
|Ошибки|`403` – не вошли на сайт|

## Как проверить API вручную

1. Войдите на сайт, откройте `/` или `/bookings/`.
2. Откройте DevTools (F12), вкладку **Network**, Fetch/XHR.
3. Создайте заявку: в списке появится `POST /api/tickets/` со статусом 201. Обновите страницу: `GET /api/tickets/` — 200.
4. Быстрое чтение без инструментов: откройте в браузере `http://127.0.0.1:8000/api/tickets/` — DRF покажет JSON в читаемом виде (нужен вход).
